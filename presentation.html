Motivation

The Problem I Wanted to Solve

  • Decision regret is universal — everyone wonders "what if?" about pivotal life choices
  • Existing AI tools are flat — chatbots give a single linear narrative, not a branching tree of outcomes
  • No structured exploration — I wanted career, lifestyle, and personality to be tracked independently across branches
Core Insight

Life isn't linear — it branches. A single decision can fork into multiple distinct futures. I needed the UI to reflect that tree structure, not just dump text.


Design Goal

Build something that feels like a professional simulation tool, not a chatbot wrapper. Data-dense, interactive, visually clean.

Prompt Engineering

  • System prompt enforces a "Timeline Architect" persona
  • Strict JSON schema defined inline with exact field names: career, lifestyle, personality, probability
  • Sibling probabilities must sum to ~100%
  • Branches must genuinely diverge — no three variations of the same outcome

Why JSON Mode?

  • Groq's response_format: json_object guarantees parseable output
  • Eliminates regex-based extraction or markdown stripping
  • Direct JSON.parse() in the API route — no post-processing pipeline needed
  • Schema validation happens at render-time through React's recursive component

Implementation

Core Prompt & Schema Contract

// Enforced JSON schema sent to LLaMA 3.3 70B via Groq { "timeline": { "id": "root", "year": "Years 1-3", "title": "Short title of this life stage", "career": "Description of professional life...", "lifestyle": "Description of personal life...", "personality": "How worldview has changed...", "probability": 100, "branches": [ { "id": "branch-1", "year": "Years 5-10", // ... same recursive structure "probability": 60, // siblings sum to ~100 "branches": [...] } ] } }

This contract is embedded directly in the system prompt. The LLM is instructed to output only the raw JSON — no markdown fences, no explanatory text. The recursive branches[] array maps directly to the React component tree.

Implementation

Recursive Tree Visualization

The Challenge

The LLM returns an arbitrarily deep nested tree. I needed a React component that could render any depth without hardcoding levels — and draw connector lines between parent and child nodes using pure CSS.

The Solution

  • Two components: TimelineTree calls renderTree() recursively; TimelineNode handles a single card
  • Flexbox layout with horizontal branching — parent on left, children stacked vertically on right
  • CSS pseudo-elements (::before, ::after) draw the L-shaped connector lines
  • Expand/collapse via CSS Grid grid-template-rows: 0fr → 1fr for smooth animation

Design

Design System Architecture

Color Tokens

Monochromatic white/slate base with a single accent: #0F52BA. No gradients, no neon. Probability uses semantic colors (green/yellow/red).

Spacing Grid

Strict 8px baseline grid. All margins and paddings are multiples of 8 via CSS custom properties (--space-1 through --space-8).

Typography

System sans-serif stack. Three levels: H1 (32px/700), H2 (24px/600), Body (16px/400). No external font requests.

Interactive States

Every button, input, and link has defined hover, active, focus-visible, and disabled states. Keyboard-navigable throughout.

Loading States

Skeleton loaders with CSS shimmer animation replace traditional spinners. Three placeholder cards mimic the final timeline layout.

Error Handling

Inline error banner with red border-left, icon, text, and dismiss button. Uses role="alert" for screen readers.

V2 — Dark Minimal
Stripped the gradients. Moved to a Vercel/Linear-inspired dark theme — black background, white text, 1px borders. Cleaner, but still felt like a "developer template."
V3 — Enterprise Light (Final)
Complete rewrite to light mode. Scandinavian minimalism. 8px grid, system fonts, single accent color, skeleton loaders, data tables, semantic HTML. Feels like a real product, not a demo.
Key Lesson Good design isn't about adding effects — it's about having a strict system and following it consistently.

Challenges

Difficulties & How I Solved Them

API Authentication (401)

Initial Gemini API key was in the wrong format. Debugged by inspecting the raw error response — the ACCESS_TOKEN_TYPE_UNSUPPORTED detail revealed it was a credential format issue, not a permissions issue.

Model Deprecation (404)

Midway through development, gemini-2.5-flash was deprecated for new keys. Had to pivot the entire backend from Google GenAI to Groq. Required rewriting the API route and switching the SDK.

Rate Limiting (429)

Hit the free-tier quota on Gemini during testing. This was the deciding factor to migrate to Groq's more generous free tier.

CSS Connector Lines

Drawing L-shaped tree connectors with pure CSS was the hardest layout problem. Required careful use of ::before / ::after pseudo-elements with :first-child / :last-child selectors to handle edge cases.

LLM Output Consistency

Without response_format: json_object, the LLM would intermittently wrap output in markdown fences or add explanatory text. Strict JSON mode solved this entirely.

Icon Compatibility

Lucide React v1.21 doesn't export brand icons (Github, Twitter). Had to discover this through build errors and switch to generic alternatives.

Summary

Key Takeaways

  • LLMs need contracts — strict JSON schemas with response format enforcement eliminate post-processing complexity
  • API resilience matters — building with a fallback LLM provider saved the project when Gemini's free tier broke
  • Design is a system, not decoration — an 8px grid with token-driven CSS scales better than ad-hoc styling
  • Recursive React is powerful — a single 20-line function renders an arbitrarily deep timeline tree
